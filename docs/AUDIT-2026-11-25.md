## Constats sans correction dans cette version

- **Retour arrière d'un enregistrement** : un fichier coffre modifié à la main peut remettre une ancienne
  version scellée d'un élément (le numéro de révision n'est pas dans l'AAD). Le déplacement entre espaces
  ou types reste refusé. Sujet de la synchronisation (D-50) : le serveur tiendra les révisions.
- **Paramètres Argon2 lus dans le fichier** sans plancher : sans effet sur un coffre existant (une
  valeur abaissée donne une autre clé, donc un refus), mais un plancher au déverrouillage serait plus sûr.
- **Verrouillage après inactivité** : réglage absent pour un coffre personnel (défaut « jamais », D-02) ;
  maquette à faire si voulu.
- **Import non branché dans l'interface** : le moteur est testé, l'écran 14 reste à coder.
- **Remplissage sur macOS** : compilé, non essayé (pas de Mac) ; pas de lecture du champ ni de l'adresse.
- **Pas d'icône de zone de notification** : fermer la fenêtre arrête les raccourcis.
- **Binaire Windows non signé** : avertissement SmartScreen au premier lancement.

## Ce qui n'a pas pu être essayé ici

Le remplissage agit sur d'autres applications (UI Automation, `SendInput`) : il ne s'essaie pas dans le
conteneur Linux ni dans un navigateur. Sa logique est couverte par des essais (séquences, formulaire en
deux pages, fenêtre changée en cours de route, collage) ; le code Windows et macOS est vérifié à la
compilation (`cargo clippy --target …`). L'essai réel se fait sur le build Windows, en pilotage d'écran.
